# Deck Building Assistant - Development Guidelines

## 1. File Structure and Naming
*   **Clear Naming Conventions:** Every file should have a clear, descriptive name that immediately indicates what it does (e.g., `Sidebar.js`, not `components.js`).
*   **Single Responsibility Principle:** Each file must have a single, clear purpose. Do not cram multiple distinct components or unrelated pieces of logic into a single file. (For example, strictly one Vue component per `.js` file).

## 2. Code Quality and Documentation
*   **Descriptive Comments:** Ensure that code is properly documented with comments describing its purpose. This is especially important for complex logic, state management, or database queries.

## 3. UI and Assets
*   **No Unicode Emotes:** Under no circumstances should Unicode emotes (e.g., 🎨, ☰) be used in the codebase or the UI. Standard text, SVG icons, or an official icon library must be used instead.
